# 网页版设计文档

日期：2026-10-11

## 背景

iOS app 装不到自己的 iPhone 上：手机装了公司的管理描述文件（workspace services），不允许信任个人开发者的 app。不想付费买 Apple 开发者账号，也不能删这个描述文件。

所以做一个网页版，取代 iOS app。iOS 代码留在仓库里，不再更新。

手表训练不是重点。心率和卡路里用 Apple Watch 自带「体能训练」app 里的「传统力量训练」记录，和网页版互不相通。

## 目标

成功标准：去健身房时用手机网页就能跟着计划练完一次、记下每一组，下次打开能看到记录和新的目标重量。

使用方式：

- 只有自己一个人用，不需要账号
- 在 iPhone 的 Chrome 上打开，添加到主屏幕，以后从主屏幕图标打开
- 主屏幕 app 和 Chrome 标签页的数据不互通，固定从主屏幕图标打开

## 范围

做：

- 今天、动作库、历史三个页面，和现在的 iPhone app 一样
- 在手机上走训练流程：做组、休息计时、结束
- 训练记录存在手机本地，自动同步到自己的 GitHub 私有仓库
- 离线可用，添加到主屏幕后全屏显示

不做：

- 手表端、HealthKit（心率和卡路里交给手表自带 app）
- 账号、多用户
- 自定义计划、图表统计（和 iOS 版一样，以后需要再加）
- 从 iOS app 迁移旧数据（iOS app 没装到手机上过，没有旧数据）

沿用 iOS 版的：

- 新手计划：A/B 交替，每个动作 3 组 x 8-12 次（平板支撑 3 组 x 20-40 秒），组间休息 90 秒
- 加重规则：第一次做的动作要先填重量；之后默认用上一次的重量；上一次所有组都做到了最高次数，这次按动作的加重步长加重；不自动减重
- 下次练 A 还是 B：和最后一次训练交替，没有记录从 A 开始

## 技术方案

纯 HTML + JavaScript，没有编译步骤，不用 npm 依赖。

### 目录和复用

- 仓库根目录新建 `web/`，放网页代码
- 动作、计划、视频的 JSON 继续放在 `Packages/FitnessCore/Sources/FitnessCore/Resources/`，示范图继续用 `FitnessApp/Assets.xcassets/ExerciseImages/` 里的 SVG，不复制两份
- 一个组装脚本把 `web/` 的代码、上面的 JSON 和 SVG 复制到 `_site/`。只复制文件，不编译。本地预览和线上部署都用它。`_site/` 不进 git
- app 图标复用 `design/icon/` 里的图标

### 代码拆分

- `plan.js`：下次练 A 还是 B、每个动作的目标重量和加重规则，照搬 `PlanEngine.swift`
- `flow.js`：一次训练的流程（做组、休息、下一组、结束），照搬 `WorkoutFlow.swift`
- `store.js`：训练记录和进行中的训练存在手机本地
- `sync.js`：和 GitHub 私有仓库同步，合并逻辑写成单独的纯函数，方便测试
- 每个页面一个文件，用网址里的 `#` 切换页面

### 部署

- 代码仓库 `ym820/personal-fitness-app` 改成公开（见「上线前的准备」）
- 推送到 `main` 后，GitHub Actions 运行组装脚本，把 `_site/` 发布到 GitHub Pages
- 网址：`https://ym820.github.io/personal-fitness-app/`

### 离线和主屏幕

- Service Worker 缓存页面、数据和示范图。没网时也能打开、照常记录，有网了再同步。B 站视频要联网
- Web App Manifest：名字、图标、全屏显示（没有浏览器地址栏）

## 页面

底部三个标签页：

- **今天**：下次是训练 A 还是 B，每个动作的组数、目标次数和目标重量，该加重时提示加了多少。底部「开始训练」按钮。点动作进详情页
- **动作库**：按部位分组的列表。详情页有示范图（起始和结束两张）、中英文名、器材、要点、B 站视频卡片（点了打开 B 站）
- **历史**：按日期列出每次训练，点进去看每组的次数和重量，可以删除一次训练。右上角「设置」入口：填 GitHub 令牌、看同步状态、手动「立即同步」

## 训练流程

1. **做组页**：动作名、第几组 / 共几组、目标次数和重量。次数和重量用 `−` / `+` 调，重量按这个动作的加重步长变化，也能直接输入数字。第一次做的动作重量是空的，要先填。点「完成这组」。「看示范」打开动作详情
2. **休息页**：90 秒倒计时，可以「跳过」或「+30 秒」，结束后自动进入下一组或下一个动作
3. **结束页**：全部做完或中途点「结束训练」，显示时长和完成了几组。保存记录，然后自动同步

细节：

- 每完成一组就把进行中的训练存到本地。练到一半关掉，重新打开接着练
- 倒计时按实际时间算，锁屏再打开时间是对的。锁屏期间时间到了不会提醒（iPhone 的网页不支持震动）
- 训练时用屏幕常亮（Screen Wake Lock）避免自动锁屏。部分 iOS 版本的主屏幕 app 里可能不生效，要实际测

## 数据

### 训练记录

沿用 iOS 版 `HistoryWorkout` / `HistorySet` 的结构，加 `id`、`durationSeconds` 和 `deleted`：

```json
{
  "id": "随机生成的唯一编号",
  "date": "2026-10-12T18:30:00+08:00",
  "durationSeconds": 1820,
  "templateId": "A",
  "sets": [
    { "exerciseId": "Leg_Press", "setIndex": 0, "value": 12, "weightLb": 90 }
  ],
  "deleted": false
}
```

- `id`：合并记录时用来认出是不是同一次训练
- `date`：开始训练的时间；`durationSeconds`：从开始到结束的秒数，历史页和结束页显示
- `value`：次数，或平板支撑这类动作的秒数
- `deleted`：删除一次训练时只做标记，不真的移除，否则下次同步会被 GitHub 上的旧记录带回来。算下次训练和显示历史时跳过已删除的记录

### 本地

所有记录存在手机本地存储里。算下次练什么、显示历史都只读本地，不联网也能用。

### GitHub 同步

- 私有仓库 `fitness-data`，一个文件 `workouts.json` 存全部记录
- 令牌：细粒度访问令牌（fine-grained personal access token），只给 `fitness-data` 一个仓库的内容读写权限，在设置页填一次
- 什么时候同步：打开 app 时、每次练完时、在设置页点「立即同步」时
- 怎么同步：下载 GitHub 上的文件，和本地记录按 `id` 合并（两边的记录都保留；同一个 `id` 只要有一边标了已删除，就算已删除），有变化就上传。上传时发现文件刚被别处改过，就重新下载、合并、再上传一次
- 换手机或数据被清：填上令牌，同步一次就拉回全部记录
- 令牌只存在手机本地，不写进代码、不提交到仓库，设置页只显示末尾几位。手机丢了的话，去 GitHub 删掉这个令牌

## 异常处理

- 没填令牌：照常用，记录只存在本地，设置页显示「未开启同步」
- 同步失败（没网、令牌过期或被删、仓库不存在）：记录照常存在本地，不影响训练。设置页显示上次成功同步的时间和失败原因，下次打开 app 自动重试
- 数据文件加载失败：显示错误提示和「重试」按钮
- 本地存储不可用（比如无痕模式）：顶部提示「当前无法保存记录」

## 界面

- 按 apple-design 和 emil-design-eng 两个设计 skill 来做
- 跟随系统的浅色 / 深色模式
- 风格「纸面」：米白底、黑字、少量橙色强调；深色模式是暖黑底、米白字。大号粗体数字（训练名、次数、重量、倒计时），列表用细线分隔，按钮是黑色胶囊
- 图标：三根逐渐升高的柱子，表示渐进加重，最高一根是橙色
- 底部第三个标签叫「记录」

## 测试

- `node --test`，不装依赖：
  - `plan.js`：A/B 交替、加重规则，用例从现有的 Swift 测试搬过来，保证和 iOS 版行为一样
  - `flow.js`：做组、休息、跳过休息、提前结束
  - 同步合并：两边都有新记录、删除标记、重复记录
- `scripts/validate_data.py` 继续检查 JSON 数据
- 手动：本地预览服务器在电脑上看；上线后在 iPhone Chrome 上添加到主屏幕，走一遍完整训练，再去 GitHub 看 `workouts.json` 有没有更新

## 上线前的准备

- 仓库改公开前，检查提交历史里有没有令牌、密码这类不该公开的东西，把结果给用户确认。提交记录里的作者名字和邮箱会公开。确认后由用户在 GitHub 上改成公开
- 用户新建私有仓库 `fitness-data`、生成细粒度令牌，步骤写进 README
- README 改成以网页版为主，写本地预览、部署、同步设置的步骤，iOS 部分标注为不再维护
